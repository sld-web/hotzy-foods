## Why Upgrade?

### 1. You're Flying Blind Without Analytics

The current website likely has no insight into customer behavior. This platform tells you:

- **What** products people look at (top pages)
- **When** they visit (peak times by hour and day)
- **How** they shop (mobile vs desktop)
- **Who** your best customers are (segments + repeat rate)
- **Where** your orders come from (geographic distribution)

Without this data, every business decision is a guess.

### 2. Complete Control, No Developer Needed

Every piece of content on the new site is editable through the admin panel:

- Hero images, titles, and descriptions
- Product details, pricing, and stock
- Promo codes and campaigns
- Team member profiles
- Shipping configuration and contact info

**What used to take a developer 2 hours now takes 30 seconds.**

### 3. Professional Brand Perception

The animated hero section, smooth transitions, and polished UI signal to customers that Hotzy Foods is a serious, premium brand. First impressions happen in milliseconds — this site makes every millisecond count.

### 4. Data-Backed Marketing Decisions

Stop guessing and start knowing:

- Run Facebook ads? Target cities where you already have traction.
- Launch a new product? Schedule the announcement for peak traffic hours.
- Worried about customer retention? Track your repeat purchase rate monthly.

### 5. Scale Without Breaking

Built on Next.js 16 + PostgreSQL, this platform handles:

- **Traffic spikes** during promotions (automatic scaling)
- **Growing product catalog** (thousands of products, no slowdown)
- **Multiple admin users** (team accounts with role-based access)
- **Future features** (the architecture supports loyalty programs, reviews, subscriptions, and more)

### 6. Competitive Advantage

Most Sri Lankan food brands have basic websites or rely on Facebook/Instagram for orders. A full-featured e-commerce platform with customer analytics puts Hotzy Foods years ahead of competitors.

## Technical Architecture

```
Frontend (Next.js 16)              Backend (tRPC v11)           Database (PostgreSQL 16)
┌─────────────────────┐           ┌──────────────────┐          ┌──────────────────────┐
│  Storefront (:3000)  │──tRPC──▶│  Shared API Layer │──Prisma──▶│  PostgreSQL          │
│  - Products          │◀────────│  @hotzy/api       │◀─────────│  - Orders            │
│  - Cart              │  types   │  - Products       │          │  - Customers         │
│  - Checkout          │  safe    │  - Orders         │          │  - Page Views        │
│                      │         │  - Analytics       │          │  - Products          │
│  Admin Panel (:3001)  │         │  - Auth            │          └──────────────────────┘
│  - Dashboard         │         └──────────────────┘
│  - Analytics         │
│  - Inventory         │         Shared Packages
│  - Orders            │         ┌──────────────────┐
│  - Customers         │         │  @hotzy/ui       │  UI Components
│  - Promotions        │         │  @hotzy/database │  Prisma Schema + Seed
│  - Settings          │         │  @hotzy/validators│  Zod Schemas
└─────────────────────┘           └──────────────────┘
```

**Key Technical Decisions:**

- **tRPC** instead of REST — End-to-end type safety. Changes in the database schema are caught at compile time, not runtime.
- **Prisma** instead of raw SQL — Type-safe database queries with auto-completion.
- **pnpm Workspaces** — Shared code between storefront and admin prevents duplication. One change to the product schema updates both apps instantly.
- **PostgreSQL** — Battle-tested, reliable, and free. Handles millions of rows without breaking a sweat.
